# 反向开单器 · OKX 智能反手引擎

写给那些**一开多就跌、一开空就涨**的人。

基于 **OKX V5 OpenAPI** 的常开反手工具。监听账户内全部 U 本位永续订单，检测到**增仓单**立即平掉并反向开仓；检测到**平仓单**自动放行，不会让你的仓位无法平掉。

它不预测行情、不判断方向、不替你做决策。判断永远是你的，执行交给机器。

> 零第三方依赖，只用 Node 内置模块。Node 18+ 即可运行。

在线演示：见仓库 About 中的 Pages 链接。

---

## 它解决什么问题

手动反手有三个不可压缩的动作：发现做反了 → 撤单/平仓 → 重新反向开仓。行情不会等这三步走完。

本工具把这三步交给程序，你只需要在 OKX App 或网页照常下单：

```
[06:48:47.491] 发现新订单 DOGE-USDT-SWAP buy 0.01 market state=filled
[06:48:49.033] 市价单/已成交，无法撤单，走「平仓 + 反开」
[06:48:49.827] → 反向 sell 0.02 张（成交 0.01 张 ×2）
[06:48:50.569] ✓ 已下反向单 ordId=4028643429057777664，耗时 3076ms
[06:48:53.183] 跳过工具自身订单（clOrdId=RV…）

── 持仓 +0.01 → -0.01，方向已翻转 ──
```

以上为实盘真实输出。

## 核心设计

### 1. 反手语义随账户模式变化

OKX 有两种持仓模式，反向的含义完全不同：

| 账户模式 | 下 1:1 反向单的结果 | 本工具的处理 |
| --- | --- | --- |
| `long_short_mode` 开平仓模式 | 多空双持，真正锁仓 | 1:1 反向 |
| `net_mode` 买卖模式 | 净持仓归零，**等于平仓** | 按 **2 倍**成交量反向，实现翻仓 |

工具启动时会读取 `posMode` 并适配。如果你的目标是锁仓而非翻仓，需要先把账户切成开平仓模式。

### 2. 市价单无法撤销，走「平仓 + 反开」

市价单属于 IOC，提交瞬间要么成交要么消失，不存在等待撤销的状态。撤单接口会返回 `51403` / `51413`。

因此状态机分两条路径：

- **限价单未成交** → 撤单成功 → 反向下单 1:1
- **市价单 / 已成交** → 读取成交量 → 反向 `2 × 成交量`，净持仓翻转

### 3. 平仓放行，避免死锁

若不加区分地对所有新单反手，你会陷入死锁：

1. 开多 → 被反手成空
2. 想平掉空单 → 这笔平仓单又被反手成多
3. 永远清不了仓，只能关掉工具

工具通过**反推成交前持仓**判断订单性质：

```
成交前持仓 = 当前净持仓 − 本单成交量（买为正、卖为负）
```

方向与成交前持仓相反 → 减仓单 → 放行。

必须用成交前持仓而非当前持仓：轮询本身有延迟，检测到订单时它通常已经成交，
当前持仓已是成交后的状态。早期版本用当前持仓判断，会导致平仓单被误判为开仓单。

### 4. 三层防循环

自动反手最大的风险是自己的反向单被自己再次反手。

| 层级 | 机制 |
| --- | --- |
| 1 | 引擎下的单 `clOrdId` 强制带固定前缀，检测到即跳过 |
| 2 | 同品种执行期加互斥锁，防止并发交叉 |
| 3 | 启动时先拉存量订单建立基线，历史单不参与 |

### 5. 断线就停机，不假装在工作

一个常驻工具最危险的状态不是崩溃，而是**看起来在运行、实际已经瞎了**。

代理节点一换，出口 IP 就变，OKX 会拒绝所有请求（`50110`）。早期版本遇到这种情况只打印一行错误然后继续轮询，
结果是一小时刷出七万字日志，而工具在此期间没有反手任何订单，使用者却以为有保护。

现在的处理分两类：

| 错误类型 | 行为 |
| --- | --- |
| 凭证 / 白名单 / 签名（`50101`、`50110`、`50113` 等） | 重试不会自愈 → **立刻停机**，打印 OKX 看到的那个 IP，并说明去哪改 |
| 网络 / 代理抖动 | 指数退避重试，日志只在首次与每 20 次时输出，不做无意义刷屏 |

另外每 5 分钟输出一次心跳，明确写着「在线 N 分钟 · 状态 · 轮询次数 · 已反手次数」，
状态异常时直接标 `⚠ 无连接`。

启动阶段拿不到存量订单时不会硬启动（否则会把历史单当新单全部反手），最多重试 6 次后报错退出。

## 快速开始

> **不需要装代理软件。** 程序内置直连通道，自己绕开国内对 OKX 域名的干扰。
> 下载 → 双击 → 三步填完 → 启动，全程不用碰命令行。

### 方式一：图形界面（推荐）

1. 装一次 [Node.js](https://nodejs.org)（LTS 版，一路下一步）
2. 下载本仓库，双击 **`启动.bat`**
3. 浏览器自动打开，进入配置向导

向导只有三步，**第 1 步全自动**：

| 步骤 | 你要做的 | 程序做的 |
| --- | --- | --- |
| 1 · 检查网络 | 不用操作，看一眼结果 | 自动解析真实 IP、握手、验证能连通 OKX，约 1 秒出结论 |
| 2 · 填 API | 粘贴 Key / Secret / Passphrase | 直接显示你的出口 IP，点一下复制，跳转链接直达 OKX 建 Key 页面 |
| 3 · 验证 | 点「开始验证」 | 真连一次 OKX，读回 UID、持仓模式、权益；失败会直说哪一步错了 |

验证通过后点「进入控制台」，顶部一按就启动反手。

之后的界面：

| 页面 | 能做什么 |
| --- | --- |
| 总览 | 持仓模式、总权益、可用余额、今日反手次数、当前持仓与挂单 |
| 总览 | **网络出口**：标出「OKX 看到的那个 IP」，一键复制；不用代理时自动指向直连 IP |
| 设置 | API 凭证、网络通道（自动 / 只直连 / 只代理）、Builder Code、轮询间隔 |
| 设置 | 「测试连接」直接告出 UID 与持仓模式，不用跑命令 |
| 日志 | 引擎的实时输出，和命令行窗口里一模一样 |

> 界面的服务只监听 `127.0.0.1`，不对外暴露；凭证仍只存在本地 `.env`。
> 关掉那个黑色命令行窗口，界面和引擎一起停。


```
[06:48:47.491] 发现新订单 DOGE-USDT-SWAP buy 0.01 market state=filled
```

### 创建 API Key 的注意事项

1. 权限只勾 **读取 + 交易**，**绝对不要勾提币**
2. 必须绑定 IP 白名单。带「交易」权限但不绑 IP 的 Key 会在 14 天后自动失效
3. 用内置直连通道时，OKX 看到的是**你家宽的公网 IP** —— 向导第 2 步直接显示，点一下就能复制
4. 如果你配了代理，OKX 看到的是**代理节点的出口 IP**，白名单要填节点 IP 而不是本机公网 IP

## 配置项

`.env`：

| 变量 | 说明 |
| --- | --- |
| `OKX_API_KEY` | API Key |
| `OKX_SECRET_KEY` | Secret Key |
| `OKX_PASSPHRASE` | 创建 Key 时自设的 Passphrase |
| `OKX_BASE_URL` | 站点域名，默认 `https://www.okx.com` |
| `OKX_NETWORK` | `auto` 先直连、不通再走代理（默认）／`direct` 只直连／`proxy` 只走代理 |
| `OKX_PROXY` | 代理地址，如 `http://127.0.0.1:7897`。留空表示不用代理 |
| `OKX_SIMULATED` | `1` 模拟盘 / `0` 实盘 |
| `OKX_BUILDER_CODE` | AI Builder 归因码，写入下单 `tag` 字段 |
| `OKX_SETUP_DONE` | `1` 表示首次向导已完成，之后启动直接进控制台 |

命令行参数：

| 参数 | 说明 |
| --- | --- |
| `--live` | 真实执行（默认演练） |
| `--instIds A,B` | 只监听指定合约，默认全部 U 本位永续 |
| `--interval 1500` | 轮询间隔（毫秒） |
| `--maxNotional 50` | 单笔名义价值上限（默认不限） |
| `--maxPerDay 30` | 每日反手次数上限（默认不限） |

## 按接口清单

| 接口 | 用途 |
| --- | --- |
| `POST /api/v5/trade/order` | 反向开仓，携带 `tag` 归因 |
| `POST /api/v5/trade/cancel-order` | 撤销未成交限价单 |
| `GET /api/v5/account/positions` | 读取净持仓，判定增仓或减仓 |
| `GET /api/v5/account/config` | 读取账户模式与 `posMode` |
| `GET /api/v5/trade/orders-history` | 轮询差量，发现新订单 |
| `GET /api/v5/public/instruments` | 读取合约面值与下单精度 |

### 网络环境：为什么不用代理也能连

中国大陆网络对 `okx.com` 做了**两层**封锁，只解决一层是不够的：

| 层 | 现象 | 常见对策 |
| --- | --- | --- |
| DNS 污染 | `www.okx.com` 解析成 `169.254.0.2`（链路本地假地址） | 换 DNS —— 没用，阿里 / 腾讯 / 系统 DNS 返回同一个污染结果 |
| SNI 阻断 | 就算拿到真实 IP，TLS 握手里 `servername=www.okx.com` 会被 RST | 只能走代理 |

本工具的直连通道同时绕开这两层：

```
1. 解析 okx.cab      这个备用域名指向同一批服务器，但没被污染
   → 拿到真实 IP：16.162.171.65 / 43.198.253.66 / 18.163.157.45（AWS 香港）

2. TLS 握手 SNI 用 okx.cab      不在黑名单，握手正常通过
   证书是 OKX 自己的 *.okx.cab，严格校验照样通过，不存在中间人风险

3. HTTP 的 Host 头写 www.okx.com   CDN 据此路由到正确的 API 站点
```

也就是说：**连的是真服务器、验的是真证书、走的是真 API**，只是换了握手时自报的域名。

配套的工程处理：

- 三个 IP **并发探测**，取握手最快的；不通自动换下一个
- 探测结果落盘缓存 30 分钟，第二次启动省掉探测，首屏约 0.9 秒
- 长连接复用，单次请求降到 300–400ms
- 直连失败会自动退回代理（如果配了的话），三层兜底

因为不经过任何中转，**OKX 看到的 IP 就是你家的公网 IP**。家宽 IP 一般几天才变一次，
变了之后界面会报 `50110` 并直接把新 IP 显示出来，复制去 OKX 更新一下白名单即可。

> 如果你的网络环境下直连仍不通（比如公司网络封了境外服务器），在设置里填一个代理地址即可，
> 网络通道选「自动」时它只作为兜底，不影响正常使用。

## AI Builder Program 接入

下单请求自动携带归因码。直接调用 OpenAPI 时字段名为 **`tag`**，长度 1–16 位字母数字
（`aiBuilderCode` 仅用于 MCP 形态，`--aiBuilderCode` 为 CLI 参数）。

```json
{
  "instId": "DOGE-USDT-SWAP",
  "side": "buy",
  "ordType": "market",
  "sz": "0.01",
  "tag": "<YOUR_BUILDER_CODE>"
}
```

在 `.env` 中配置 `OKX_BUILDER_CODE` 即自动生效。未配置时发单不带该字段。

## 已知限制

- **检测延迟**：依赖 `orders-history` 轮询，端到端约 6 秒（API 延迟约 2s + 轮询间隔 + 执行耗时）。
  需要更低延迟需改用私有 WebSocket `orders` 频道，当前版本尚未实现。
- 仅支持 U 本位永续合约，现货与币本位未适配。
- 不处理部分成交后的剩余挂单与成交量的复杂组合场景。
- 图形界面需要在 Windows 上安装 Node.js 18+（`启动.bat` 会自动检查并提示下载地址）。
